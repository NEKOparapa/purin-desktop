# Wintermute Desktop

Wintermute 的 Windows/macOS 桌面终端，使用 Electron、React 和 TypeScript。

## 连接 Agent

1. 启动 Wintermute 后端并启用 HTTP 接口。后端示例 `config/interfaces.example.json` 将 `http-desktop` 绑定到用户 `local` 的 `main` 会话，令牌由 `WINTERMUTE_HTTP_TOKEN` 提供。每台设备使用自己的终端 ID 和令牌，同一用户的终端可以绑定到同一个会话。
2. 打开侧栏底部的“设置”，默认进入“连接”。填写服务地址（本机默认为 `http://127.0.0.1:8080`）、终端 ID 和令牌，点击“验证并保存”。已保存的终端 ID、服务地址和连接状态也在这里查看。桌面端使用操作系统凭证加密保存令牌。
3. 应用直接打开对话。输入问题后按 Enter 发送，Shift + Enter 换行，等待期间可继续补充。同一会话里来自其他设备的发言，以及定时提醒触发的 Agent 回复，也会自动显示。提醒触发的回复标记为“Wintermute · 通知回复”。

侧栏“设置 → 外观”提供跟随系统、浅色和深色，默认跟随系统。选择立即生效，保存在当前设备上，连接 Agent 前也可以设置。

在“设置 → 接口密钥”查看后端模型密钥的用途、配置状态和脱敏尾号。选中需要更改的一项，输入新密钥并保存。共用同一项密钥的用途列在一起，保存后从下一次模型请求起生效。远程管理使用 HTTPS，本机调试可连接回环地址。后端须在对应 HTTP 终端配置中开启 `manage_api_keys`。

桌面端启动及运行期间会读取后端会话历史。滚动到顶部可加载更早的消息。后端清空后，桌面端下一次成功同步就会清除旧聊天。本机只保存待发送或待确认的请求与重试状态；发送超时后点击“重试发送”会复用原消息 ID。处理失败或中断时，可以点“重新提问”生成新请求。

## 接收设备通知

侧栏「通知」显示主 Agent 发给本终端的提醒。展开标题可查看正文和附件，点击文件名选择本机保存位置。桌面端运行时约每 5 秒检查一次待收通知，窗口在前台时显示应用内横幅，在后台时使用系统通知。已过期的提醒可在收件箱查看。退出程序期间的通知会在下次启动后补收。

## 查看主 Agent 的日历

连接终端后，点侧栏「日历」。月历按电脑的本地时区显示当前会话的安排。选中日期可查看当天的触发时间、安排内容以及是否已经通知主 Agent。可在对话里让 Agent 新建、改期或取消安排。打开的日历会自动刷新，也可以手动刷新。

## 浏览后端记忆

在「记忆 → 用户档案」可以查看当前终端所属用户的基本信息、长期偏好、日常习惯、近期状态和常用时间段。打开页面或切回窗口时会从后端读取最新档案，页面可见时每分钟刷新一次，也可手动刷新。后端需要支持 `GET /v1/profile` 并为该用户配置档案路径。

首次打开时也能看到初始模板。有了资料后，可以展开「查看初始模板」对照原有栏目。页面标出当前档案是否会进入主 Agent 下一轮的系统提示。常用时间段单独供后台判断空闲时段。连接旧版后端时，已填写档案的生效状态可能显示为未知。

连接终端后，点侧栏“记忆”。打开的“对话历史”会自动刷新。这里保留用户原话、Agent 回复、工具调用与结果、后台通知和活动更新。“时间线历史”单列当时追加到会话的合并更新。要追看某条记录的来源，可切换到交流、通知、感知或切片层，往前加载更早的记录。同一会话的其他终端产生的记录也可以在这里查看。

时间线历史显示写入会话的活动文字。要查看桌面自动截图，打开「记忆 → 感知层 → 格式化信息」，找到已结束的那次应用停留，可一起查看工作对象、画面识别结果和采集到的代表帧。「原始信息」展示完整的已入库事件 JSON。桌面端会自动加载记忆页中可见的截图，包括切片层中主动分享的图片和已展开的原始资料。录音等其他附件可点击文件名下载。旧版后端接收的桌面停留只保留了采集信息与识别文字，原图无法补回。

在「感知层」选择「压缩信息」，或在「切片层」选择「压缩对照」，点开一个批次即可比对活动输入、规则摘要和已生成的 AI 摘要。展开「查看原始资料」可追到原事件、附件和已保存的提取结果。感知记录在进入压缩批次前就可从「原始信息」和「格式化信息」中查看。要核实主 Agent 实际收到的文字，点击「查看已投递的时间线」。

## 桌面活动与分享

连接终端后，在“终端设置 → 信息采集”分别启用需要的来源。

- **桌面活动。** 开启“分享桌面活动”后，客户端每 15 秒采样，发现应用切换后会在 5 秒门槛复查。离开已确认的应用后，感知层收到一条 `desktop.window_span`，包含起止时间、估算停留秒数和工作对象的变化顺序。短暂误切后返回沿用原时段，并扣除观察到的离开时间。macOS 读取其他应用的窗口标题可能需要辅助功能和自动化权限。
- **浏览器。** 启用“浏览器接入”，打开扩展文件夹，在 Chrome 或 Edge 的扩展管理页加载已解压的扩展，然后复制配对码到扩展。通过工具栏分享当前页，或选中文字后使用右键菜单。自动采集要对每个站点单独启用，只发送前台页的域名和标题。[扩展操作说明](browser-extension/README.md)
- **按内容变化选取代表帧。** 在信息采集设置中启用桌面活动和前台窗口截图。客户端从已确认的窗口选取稳定画面及有明显变化的后续画面，每段最多四张，使用所选间隔控制采集预算。窗口切换时使用此前的候选帧。停留结束后，图片随这段感知一起提交，后端识别并保存可预览的原图附件。离线或识别暂时失败时保留本地待发材料。关闭截图会清理待传图片。macOS 需要录屏权限。
- **主动分享。** 对话输入框旁点“分享”。可输入或粘贴文字，截取指定窗口或屏幕、粘贴一张图片，或录制最长 5 分钟的麦克风声音。检查文字、预览图片或试听后点“确认分享”。macOS 首次截图或录音时需开放相应系统权限。

主动分享的文字和图片进入切片；录音按单声道 Ogg/Opus 上传并在服务端转录。每台终端有独立待发队列，可在信息采集设置中重试或丢弃失败的上传。

## 开发

使用 Node.js **24 LTS** 和 npm，依赖由 `package-lock.json` 锁定。

```sh
npm ci
npm run dev
```

`dev` 同时启动 Vite 与 Electron；关闭开发命令时两个进程一并结束。只预览网页可运行 `npm run dev:web`，访问 `http://127.0.0.1:5173`。端口固定，若已被占用会报错，避免 Electron 加载错误服务。

```sh
npm run build
npm start
```

以上命令使用 Electron 加载构建后的本地文件，不依赖开发服务器。

## 打包

```sh
npm run pack       # 当前系统的应用目录，输出 release/
npm run dist:win   # Windows NSIS 安装包，x64 + arm64
npm run dist:mac   # macOS DMG，Intel + Apple Silicon；在 macOS 上执行
```

Windows 本机预览程序位于 `release/win-unpacked/Wintermute.exe`，请保留整个目录。可以拖动窗口顶部的空白处移动窗口，使用系统窗口按钮最小化、最大化或关闭窗口。最小窗口尺寸为 860×680。macOS 保留原生菜单，关闭窗口后应用继续运行。Windows 关闭所有窗口时退出。

当前构建使用 Electron 默认应用图标及本地未签名配置。

## 验证

```sh
npm run lint
npm run build
npm run test:agent
npm run test:e2e
node scripts/smoke.cjs
node scripts/smoke.cjs release/win-unpacked/Wintermute.exe
```

`test:agent` 使用本地 HTTP 服务验证重试、跨终端会话同步、服务端清空、收件箱确认和活动采集去重。浏览器 E2E 使用本机 Chrome 测试导航、未配置时的引导和小窗口布局。纯网页预览没有 Electron 系统采集及凭证桥接。

`scripts/smoke.cjs` 会使用临时应用资料启动真正的 Electron 窗口，验证连接、开启与关闭系统采集、发送会议问题、从后端加载回复和重启后的会话同步。默认运行本地测试 HTTP 服务。要连接实际后端，可在测试进程设置 `WINTERMUTE_TEST_URL`、`WINTERMUTE_TEST_TOKEN` 和可预期的回复片段 `WINTERMUTE_TEST_REPLY`，并为这次测试绑定终端 `http-desktop`。macOS 打包程序可传入 `.app/Contents/MacOS/Wintermute`。

## 结构

- `src/App.tsx`、`src/components/agent-settings.tsx`：会话、终端设置和主页。
- `src/components/memory-browser.tsx`：后端历史浏览、分页和附件保存入口。
- `src/components/ui/`：由 shadcn CLI 生成并纳入源码的 Button、Badge、Dialog。
- `src/index.css`、`src/App.css`：主题和响应式布局。
- `electron/main.cjs`、`electron/preload.cjs`：应用生命周期和类型受限的 IPC 接口。渲染器启用 sandbox/contextIsolation。
- `electron/agent.cjs`、`electron/activity.cjs`：主进程内的认证、持久收发、队列和系统活动采样。
- `electron-builder.yml`：Windows/macOS 打包目标。

构建资源使用相对路径，支持 Electron 的 `file://` 加载。生产页面使用 CSP，Vite 开发模式单独允许 React 热更新所需的内联脚本。

可继续通过 `npx shadcn@latest add <component>` 添加组件。参考：[shadcn Vite 配置](https://ui.shadcn.com/docs/installation/vite)、[Electron 上下文隔离](https://www.electronjs.org/docs/latest/tutorial/context-isolation)。
